# COMMERCE DOMAIN

## 1. commerce_ga_data

Google Analytics behavioral data scoped to commerce pages — top-of-funnel traffic and click tracking.

| Column | Type | Description |
|--------|------|-------------|
| `clean_page_url` | varchar | The cleaned article/page URL (protocol and query parameters removed). |
| `date` | varchar | The date the transaction or interaction occurred. |
| `default_channel_grouping` | varchar | Automated classification by Google Analytics bucketing traffic into broad categories like Organic Search, Paid Search, Social, or Direct. |
| `hostname` | varchar | Standardized brand name for consistent reporting across sources. |
| `outbound_clicks` | bigint | Tracks when a reader clicks an affiliate link (e.g., a "Buy Now" button for Amazon or Walmart) that takes them off the New York Post site to a retailer. |
| `page_url` | varchar | The specific web address of the article. |
| `pageviews` | bigint | The total number of times a commerce page was loaded or reloaded. |
| `region` | varchar | The geographic location (Country, State, or City) of the Viewer. |
| `utm_campaign` | varchar | Identifies the specific marketing push or theme. |
| `utm_medium` | varchar | Identifies the "vehicle" or type of link used (e.g., social, email, cpc for paid ads, or referral). |
| `utm_source` | varchar | Identifies the platform sending the traffic (e.g., facebook, google, twitter, or internal_recirc). |

| Column | Type | Description |
|--------|------|-------------|

| `category` | varchar | The broad classification of the products being sold. |
| `clicks` | double | Total count of clicks recorded. |
| `cpc` | double | Generated by an ad — the cost a brand paid the Post for that click. |

| `earnings` | double | The actual dollar amount of commission or ad revenue the New York Post has cleared. |
| `impressions` | bigint | The total number of times a specific product, link, or ad was seen by readers. |
| `product_group` | varchar | A sub-classification within a category that groups similar items together. |
| `slot_name` | varchar | The specific location or placement on a webpage where an ad or affiliate link is located. |
| `title` | varchar | The specific name of the product or the headline of the article driving the data. |

## 3. commerce_sales_aggregated_data

Pre-aggregated rollup of commerce sales metrics with built-in period-over-period comparisons (week prior, month prior, year prior). This is the **gold layer / BI-ready table** for commerce executive reporting.

| Column | Type | Description |
|--------|------|-------------|
| `aov` | double | Tracks the average dollar amount a reader spends when they make a purchase through a link on the Post. |
| `aov_month_prior` | double | Compares current AOV against the same period last month. |
| `aov_week_prior` | double | Compares current AOV against the previous 7 days. |
| `aov_year_prior` | double | Compares current AOV against the same date/period last year (crucial for year-over-year growth analysis). |
| `clicks_month_prior` | double | Compares current clicks against the same period last month. |
| `clicks_week_prior` | double | Compares current clicks against the previous 7 days. |
| `clicks_year_prior` | double | Compares current clicks against the same date/period last year. |
| `commission_month_prior` | double | Compares current commission against the same period last month. |
| `commission_week_prior` | double | Compares current commission against the previous 7 days. |
| `commission_year_prior` | double | Compares current commission against the same date/period last year. |
| `conversion_rate` | double | The percentage of clickers who actually bought something. |
| `conversion_rate_month_prior` | double | Compares current conversion rate against the same period last month. |
| `conversion_rate_week_prior` | double | Compares current conversion rate against the previous 7 days. |
| `conversion_rate_year_prior` | double | Compares current conversion rate against the same date/period last year. |
| `date` | date | The date the transaction or interaction occurred. |
| `epc` | double | Earnings Per Click — exactly how much commission the Post earns for every single click generated. |
| `epc_month_prior` | double | Compares current EPC against the same period last month. |
| `epc_week_prior` | double | Compares current EPC against the previous 7 days. |
| `epc_year_prior` | double | Compares current EPC against the same date/period last year. |
| `event` | varchar | Used to categorize data by specific shopping holidays, seasonal campaigns, or internal promotions. |
| `fiscal_month` | varchar | Fiscal month index (July = 1, August = 2, etc.). |
| `fiscal_quarter` | varchar | Fiscal quarter (Q1–Q4) based on the July–June cycle. |
| `fiscal_year` | varchar | Fiscal year based on a July–June cycle. |
| `orders_month_prior` | double | Compares current orders against the same period last month. |
| `orders_week_prior` | double | Compares current orders against the previous 7 days. |
| `orders_year_prior` | double | Compares current orders against the same date/period last year. |
| `sales_month_prior` | double | Compares current sales against the same period last month. |
| `sales_week_prior` | double | Compares current sales against the previous 7 days. |
| `sales_year_prior` | double | Compares current sales against the same date/period last year. |
| `total_clicks` | double | Total count of clicks recorded. |
| `total_commission` | double | Net commission earned from the sale. |
| `total_orders` | double | Total count of successful transactions/orders. |
| `total_sales` | double | Gross sales volume (Revenue). |

**Key insight:** This table has built-in trend columns (`_week_prior`, `_month_prior`, `_year_prior`) for every core metric — this is the agent's preferred table for any "compare to last week/month/year" question. No need to self-join `commerce_sales_data` for period comparisons.

## 4. commerce_sales_data

The core commerce transaction fact table. One row per click/transaction event, enriched with product, content, and fiscal metadata.

| Column | Type | Description |
|--------|------|-------------|
| `asin` | varchar | Extracted 10-digit Amazon Standard Identification Number. Defaults to 'Others' for non-Amazon sources. |
| `asin_category` | varchar | Product category enriched from the ASIN master table. |
| `authors_updated` | varchar | Cleaned author field resolving specific aliases (e.g., mapping 'rkingnyp' to 'Dana Wood'). |
| `brand` | varchar | Product brand name enriched from the ASIN master table. |
| `category` | varchar | Identifies if the merchant belongs to 'Streaming Category' or 'Other'. |
| `click` | double | Total count of clicks recorded. |
| `commission` | double | Net commission earned from the sale. |
| `content_type_subid` | varchar | Extracted content category from SubID (e.g., 'SAL', 'NL'). |
| `date` | date | The date the transaction or interaction occurred. |
| `event` | varchar | Significant commerce events (e.g., holiday sales) joined by date. |
| `evergreen_articles_ind` | boolean | TRUE if the article URL exists in the evergreen articles master list. |
| `fiscal_month` | varchar | Fiscal month index (July = 1, August = 2, etc.). |
| `fiscal_quarter` | varchar | Fiscal quarter (Q1–Q4) based on the July–June cycle. |
| `fiscal_year` | varchar | Fiscal year based on a July–June cycle. |
| `hostname` | varchar | Standardized brand name for consistent reporting across sources. |
| `is_amazon_data` | boolean | TRUE if the link is identified as an Amazon-sourced transaction. |
| `is_blackfriday` | boolean | TRUE if the content relates to the Black Friday shopping event. |
| `is_primeday` | boolean | TRUE if the content or date relates to the Amazon Prime Day event. |
| `link` | varchar | The specific outbound affiliate link clicked. |
| `link_placement_subid` | varchar | Extracted placement location from SubID (e.g., 'TXL', 'BTNL'). |
| `merchant_name` | varchar | The name of the retailer/merchant (e.g., Nordstrom, Hulu, Amazon). |
| `ncaurl_ind` | boolean | TRUE if the article URL exists in the NCAURL master list. |
| `network_name` | varchar | The affiliate network (e.g., Impact, CJ, Rakuten, Amazon, LS). |
| `orders` | double | Total count of successful transactions/orders. |
| `page_url` | varchar | The cleaned article/page URL (protocol and query parameters removed). |
| `primary_author` | varchar | The first author listed in the cleaned authors string. |
| `primary_tag` | varchar | The primary content tag assigned to the article in GA. |
| `primary_tag_updated` | varchar | Cleaned primary tag with fallbacks to network name if missing. |
| `product_group` | varchar | Product grouping enriched from the ASIN master table. |
| `product_name` | varchar | The name of the product involved in the transaction. |
| `pub_date` | date | The original publication date of the article from GA metadata. |
| `sale` | double | Gross sales volume (Revenue). |
| `source` | varchar | The data origin (e.g., 'TRX', 'Amazon', 'VividSeats'). |
| `sub_id` | varchar | The raw tracking ID string (e.g., 'nyp-SAL-TXL--'). |
| `title` | varchar | Specific product title enriched from the ASIN master table. |
| `transaction_type` | varchar | Categorization of the payout model (CPC, CPA, or Unknown). |
| `valid_sub_id` | boolean | TRUE if the SubID contains at least one recognized brand, content type, or placement code. |
| `website_name` | varchar | The high-level brand (NY Post, PageSix, Decider) based on URL patterns. |
| `website_subid` | varchar | Extracted brand code from SubID (e.g., 'nyp', 'dec'). |

# EDITORIAL - EXECUTIVE DOMAIN

## 18. beat_article_level_data

Article-level performance metrics broken down by traffic channel, device, and geography — the core editorial content table.

| Column | Type | Description |
|--------|------|-------------|
| `authors` | varchar | The name(s) of the reporter(s) or columnist(s) who wrote the piece. |
| `channel_grouping` | varchar | High-level attribution channels mapped from web analytics (e.g., Organic Search, Organic Social, Direct, Email/Newsletter, Referral). |
| `date` | date | The specific day this slice of traffic occurred. |
| `device_category` | varchar | Categorizes readers by hardware type (e.g., Mobile, Desktop, Tablet). Helps mobile editors optimize layouts, headline breaks, and ad placements. |
| `edition` | varchar | Likely represents targeted editions or distribution variants (e.g., US, UK, or print-sync vs. digital-only regional variants). |
| `geo_region` | varchar | The country, state, or metro region of the audience (e.g., New York, California, United Kingdom). |
| `hostname` | varchar | Indicates the specific digital property hosting the piece (e.g., nypost.com, pagesix.com, decider.com). |

# Cross-Domain Reference Notes

## Common Join Keys Across Tables

| Key | Used In | Purpose |
|-----|---------|---------|
| `post_id` | beat_article_level_data, sportsplus_editorial_insights, sportsplus_editorial_marketing | Joins article-level metrics to CMS article identity |
| `hostname` | commerce_ga_data, commerce_sales_data, beat_user_level_data_*, beat_article_level_data | Joins across NYP's multi-brand properties (nypost.com, pagesix.com, decider.com) |
| `date` | Nearly all tables | Universal time-series join key |
| `page_url` / `clean_page_url` / `page_title` | commerce tables, beat tables | Content-level joins between commerce and editorial |
| `primary_tag` | beat_article_level_data, sportsplus_editorial_insights, beat_direct_users_content_daily | Topic/theme-level aggregation across domains |

## Fiscal Calendar (Commerce Domain Only)

NYPost commerce reporting uses a **July–June fiscal year**:
- Fiscal Month 1 = July, ... Fiscal Month 12 = June
- Always use `fiscal_year`/`fiscal_quarter`/`fiscal_month` for commerce financial period comparisons, not calendar year

## Tables With Built-In Period Comparisons (No Self-Join Needed)

These tables already contain `_week_prior`, `_month_prior`, `_year_prior`, `_wow`, `_mom`, `_dod` columns — prefer these over manually self-joining the raw fact tables:
- `commerce_sales_aggregated_data` (week/month/year prior for aov, clicks, commission, conversion_rate, epc, orders, sales)
- `sportsplus_audiencegeo_curated` (week-over-week for conversions, sports_pvs)
- `sportsplus_overview` (dod, wow, mom for all KPIs)

## Brand/Hostname Values (Cross-Domain)

The NYP umbrella includes multiple properties referenced via `hostname` or `website_name`:
- `nypost.com` (NY Post — flagship)
- `pagesix.com` (Page Six — entertainment/celebrity)
- `decider.com` (Decider — streaming/entertainment guide)

## Data Type Notes

- Several "count" columns use `double`/`decimal` instead of `integer`/`bigint` (e.g., `beat_direct_users_daily.users`, `commerce_sales_data.orders`) — this typically indicates the value is statistically modeled/weighted/sampled rather than a raw count. Treat these as estimates, not exact counts, when generating synthetic data or writing business rules.
- `processed_timestamp` columns (timestamp(6) with time zone) are audit/log fields for data pipeline tracking — generally not used in business-facing queries, but useful for data freshness checks.
